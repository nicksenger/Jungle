# Welcome to the Jungle

This is an example application that renders the progression of several `jungle` `Animal`s playing a rendition of "Welcome to the Jungle," the opening track for Guns'n'Roses debut album, Appetite for Destruction (1987).

All timing and notation data is contained within the `Flow` types themselves, their associated const generics, or the state over which they operate. Raw PCM audio (including voice synthesis) is generated by the `Effect`s and then rendered by [cpal](https://github.com/RustAudio/cpal).

The rendered DAGs for each `Flow` are from `jungle-vision` with some light customizations for the example.

The example includes features for enabling or disabling the various backends: `postgres` (recommended for distributed systsems), `redb` (recommended for isolated persistent deployments), etc.

Each `Animal` is gated behind a feature-flag: `bass`, `drums`, `leadguitar`, `rhythmguitar`, `vocals`. This is because the long `Flow`s used in this `Jungle` put high load on rustc (the chatbots are convinced that it is not the trait solver.. _ha_). You will notice that compile times are unusually high for the volume of code when all features are enabled:

```
cargo run --example welcome --release --features viewer,audio,video,vocals,bass,drums,leadguitar,rhythmguitar
```

This is most likely due to a combination of both:
- shitty proofs used for `jungle` (typosaurus in particular is mostly exploratory and not optimized)
- rustc is not tailored to this obscure use-case
